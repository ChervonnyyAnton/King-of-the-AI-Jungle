# 🔄 Review & Remediation: Cycle 148 — Test Data Lifecycle Management

## 🎯 Objective
Define a test data lifecycle management policy covering the creation, usage, and deletion of synthetic and mock data to ensure data minimization and proper cleanup.

## 📋 Findings & Remediation

| Area | Finding | Severity | 2-Axis Impact | Remediation |
|------|---------|----------|---------------|-------------|
| **Documentation — Test Data Lifecycle** | Workshop artifacts that contain synthetic data (generated by `scripts/gen-synthetic-data.sh` or mock responses from `docs/requirements/MOCK-API/`) have no defined lifecycle. They are created, used in exercises, and then left on disk indefinitely. Over time, this accumulates stale test data that may become inconsistent with the mock app's schema. No cleanup procedure exists. | **Medium** | **Engineers (D1–D4):** Accumulated test fixture files that don't match current app schema cause test failures. **Scouts (A1–A4):** Confusion about which test data files are current vs. legacy. | Created `docs/tools/TEST-DATA-LIFECYCLE-GUIDE.md` — a lifecycle management guide covering: (1) **Creation** — use `scripts/gen-synthetic-data.sh` for new data; (2) **Storage** — synthetic data lives in `docs/requirements/MOCK-API/` or `tests/fixtures/`; (3) **Versioning** — each dataset includes a `meta.version` field; (4) **Cleanup** — run `scripts/cleanup-test-data.sh` at workshop end to remove stale files; (5) **Retention** — test data older than 30 days must be deleted. Also added a `scripts/cleanup-test-data.sh` script for workshop-end cleanup. |

## 📂 Updated Files
- **`docs/tools/TEST-DATA-LIFECYCLE-GUIDE.md`**: New file — comprehensive test data lifecycle management guide with creation, storage, versioning, cleanup, and retention policies.
- **`scripts/cleanup-test-data.sh`**: New file — workshop-end cleanup script that removes synthetic data files older than 30 days and reports what was removed.

## 📐 Risk Assessment
- **Risk Score:** 2 × 3 = **6** → **Medium**
- **Probability:** Possible (2) — test data accumulation is a common workshop issue.
- **Impact:** Medium — stale test data causes test failures and confusion for future workshop sessions.

## 🔄 R&R Rule Derivation

> **Rule DP-8 — Test Data Lifecycle & Cleanup:** All synthetic and mock data files must follow a defined lifecycle: (1) Created via approved tools (`gen-synthetic-data.sh`, mock API corpus); (2) Stored in designated directories (`docs/requirements/MOCK-API/`, `tests/fixtures/`); (3) Versioned via `meta.version` field; (4) Cleaned up via `scripts/cleanup-test-data.sh` at workshop end; (5) Retained for maximum 30 days post-workshop unless explicitly archived. Test data older than 30 days is considered stale and must be removed to maintain data minimization principles.
