# 🔄 Review & Remediation: Cycle 141 — GDPR-Compliant Synthetic Data Generator

## 🎯 Objective
Identify and remediate the absence of a deterministic synthetic data generator script, addressing the risk of participants accidentally using real customer data (PII) when testing the mock PDF configurator's JSON Import and Data Grid features.

## 📋 Findings & Remediation

| Area | Finding | Severity | 2-Axis Impact | Remediation |
|------|---------|----------|---------------|-------------|
| **Technical — Test Data Quality** | No synthetic data generator exists. Participants who paste real data into `mock/index.html`'s Data Grid or JSON Import risk exposing PII to AI models (AGENTS.md §Data Privacy). The existing `DEFAULTS.gridData` in `mock/index.html` uses generic placeholders ("Tester A", "SDET B"), but these are insufficient for structured testing of customer records. | **High** | **Scouts (B1–B4):** Manual test data creation without synthetic generators leads to PII leakage. **Engineers (D1–D4):** Automated tests that reference hardcoded real data in fixture files. | Created `scripts/gen-synthetic-data.sh` — a bash script that generates deterministic, GDPR-compliant synthetic customer records in JSON format. Output uses fictional names, fake domains (@jungle.test, @sandbox.dev), and synthetic IDs (e.g., `CUST-0001`). All data passes a built-in PII filter that rejects any email from real domains. |

## 📂 Updated Files
- **`scripts/gen-synthetic-data.sh`**: New file — deterministic synthetic data generator with PII-safe patterns, configurable record count, and GDPR compliance markers.

## 📐 Risk Assessment
- **Risk Score:** 3 × 4 = **12** → **High**
- **Probability:** Likely (3) — participants will naturally use real-world examples when creating test data.
- **Impact:** High — PII exposure violates GDPR Article 5(1)(c) and the workshop's own PII Protection rule (SEC-5).

## 🔄 R&R Rule Derivation

> **Rule DP-1 — Synthetic Data Requirement:** All test data used in workshop exercises must be generated by a synthetic data generator (`scripts/gen-synthetic-data.sh`) or manually constructed using the workshop's placeholder conventions (e.g., `cust-001`, `jane.doe@jungle.test`). Real customer data, real email addresses, and real identifiers are strictly prohibited in test inputs. Every generated dataset must include a `meta` block with `generated_by`, `generation_timestamp`, and `gdpr_compliant: true`.
