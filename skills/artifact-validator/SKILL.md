# 🛡️ Skill: Artifact Validator

**Purpose:** Validates that an AI-generated artifact (e.g., `TEST-PLAN.md`, `RISK-ANALYSIS.md`) meets the **2-Axis standards**, **ISTQB basics**, and **R&R Rules** before it is submitted to the instructor or committed.

> **Trigger:** Use this skill whenever a participant finishes an artifact and wants to self-check before submission, or when the instructor needs to quickly audit a participant's work.

---

## 🔍 Validation Rules by Artifact Type

### 1. Risk Analysis (`docs/requirements/RISK-ANALYSIS.md`)
- [ ] **Categories:** Covers ≥3 risk categories (Technical, Security, UX, or equivalent).
- [ ] **Mitigations:** Every Critical/High risk has a documented mitigation strategy.
- [ ] **ISO 29119 Compliance:** Includes risk description, likelihood, impact, and priority.
- [ ] **Fact-Check:** All risks are traceable to specific requirements in `docs/requirements/TICKETS/`.

### 2. Test Plan (`docs/requirements/TEST-PLAN.md`)
- [ ] **ISTQB Techniques:** Explicitly references ≥3 ISTQB Test Design Techniques (e.g., Equivalence Partitioning, Boundary Value Analysis, Decision Tables).
- [ ] **Test Cases:** Contains ≥5 test cases with clear expected results.
- [ ] **Coverage:** Positive, Negative, and Accessibility scenarios are included.
- [ ] **Traceability:** Each test case maps back to a specific JIRA ticket (e.g., `JIRA-102`).

### 3. Playwright Specs (`tests/*.spec.ts`) — Engineers Only
- [ ] **Selectors:** Uses `data-testid` attributes (no fragile CSS/XPath selectors).
- [ ] **User Journey:** Tests navigate the app in logical user-flow order.
- [ ] **Edge Cases:** Includes at least 1 negative/edge-case test (not just happy path).
- [ ] **Assertions:** Covers both UI state (DOM) and toast/notification behavior.
- [ ] **Coverage:** Achieves ≥80% requirements coverage against `docs/requirements/TICKETS/`.

### 4. Budget Log (`BUDGET-LOG.md`)
- [ ] **Tracking:** Records operator, timestamp, artifact type, cost, and prompt version for every major task.
- [ ] **Compliance:** Total spend does not exceed the $50 USD limit.
- [ ] **Format:** Uses ISO 8601 timestamps and consistent currency formatting.

### 5. Prompt Blocks (Generated by Jungle Prompter)
- [ ] **Safety Filters:** Includes "No Malicious Code", "No System Prompt Disclosure", and "No Rule Disregard" clauses.
- [ ] **Context Pruning:** Explicitly limits token usage (e.g., `max_tokens: 8192`, rolling window).
- [ ] **Fact-Check Gate:** Requires citing exact source files for factual claims.

## 📊 Validation Output Format

Always return the validation result in this format:

```markdown
## 🛡️ Artifact Validation Report

**Artifact:** `<path/to/artifact>`
**Status:** ✅ PASS / ⚠️ PARTIAL / ❌ FAIL
**Score:** `<X>/5`

### ✅ Passed Checks
- [x] `<passed-check-1>`
- [x] `<passed-check-2>`

### ⚠️ Failed Checks (Remediation Required)
- [ ] `<failed-check-1>` — *Hint: How to fix it*
- [ ] `<failed-check-2>` — *Hint: How to fix it*

### 📝 Verdict
<1-sentence summary. E.g., "Good start, but you need to add a 3rd ISTQB technique to the Test Plan." >
```

---

## 🧠 Self-Healing Loop

If the validation fails or returns **⚠️ PARTIAL**, the skill MUST:
1. **State the exact failure** (quote the missing requirement).
2. **Propose a concrete fix** (include code, text, or structure changes).
3. **Apply the fix automatically** (if the artifact is editable).
4. **Re-validate** to ensure the remediation worked.
